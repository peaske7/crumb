# crumb v0–v1 PRD

Status: agreed 2026-09-28. Design details: `docs/design.md`.

## Problem Statement

The first user (Lymo) runs one backend per git worktree on a VPS ("leases") so that
several branches can be tested end to end at once. A lease is eight pieces on
two machines: the worktree directory, a Mutagen sync session, the frontends'
env-file wiring and an SSH tunnel on the Mac; a replica directory, a
port slot file, a Docker Compose project (backend + Redis) and a branch
database on the VPS. A shell script creates all of them, but nothing keeps
them in agreement and nothing shows them together.

On 2026-09-28 at 21:01 JST this looked like:

- 6 of 7 leases pointed at worktrees that no longer existed. Their containers
  and sync sessions were still running and held about 1.6 GB of RAM on a 16 GB
  box that must keep 3 GB free.
- One orphaned backend had restarted 25,943 times.
- The current worktree's lease had been dead for 22 minutes with
  `ERR_MODULE_NOT_FOUND`: a dependency landed that day and the shared image was
  three days old. Nothing said so.
- Ten branch databases existed; three had no lease and no record of origin.
- No SSH tunnels were up. The fix that made live WebSockets work against a
  lease had been uncommitted in a worktree and was deleted with it.

From the developer's side: finding out whether "my code is actually running"
takes a debugging session, deleting a worktree silently leaks a backend, and
the tooling itself is edited in throwaway worktrees and loses its fixes.

## Solution

`crumb`, a lazygit-style terminal UI with plain CLI subcommands, in its own
repository and installed once on the Mac.

- One table with a row per lease, joined across both machines, with a column
  per freshness layer (SYNC, BUILD, DEPS, SCHEMA, WIRED), the port, memory and
  a derived state (starting, healthy, crashed, stopped, orphaned, database
  only).
- A detail pane that says why a layer is behind, a logs pane, and a command
  log that prints every shell command crumb ran.
- Reaping of orphaned leases after showing exactly what will be stopped.
- In v1, crumb owns the lease lifecycle (up, restart, stop, down, drop,
  migrate, tunnel) and the shell script is deleted.

crumb stores nothing of its own. Every fact is read from the system that owns
it, and the lease name is the join key.

crumb is also easy to install and set up, and not tied to one team's setup
(agreed 2026-09-28, see "Setup, drivers and agents" below):

- One static binary from one GitHub release, installable through mise,
  Homebrew, a checksum-verified shell installer, or `cargo binstall`.
- `crumb init` detects the repo's compose file, Mutagen config, SSH host,
  migrations and env files, asks at most three questions, and writes a
  commented `crumb.toml`. `crumb doctor` checks every prerequisite and prints
  the fix for anything missing.
- A lease is the worktree plus a few pieces (host, code, runtime, port,
  database, wiring, checks), each with a built-in driver or a user-supplied
  command. The first user's VPS setup is one configuration among several.
- `crumb agents install` installs crumb's agent skill for Claude Code and
  Codex.

## User Stories

1. As a developer, I want to see every lease on the host in one table, so that I know what is running without running nine commands.
2. As a developer, I want each lease's worktree shown next to it, so that I can tell which branch a backend belongs to.
3. As a developer, I want leases whose worktree no longer exists marked as orphaned, so that I notice leaked backends.
4. As a developer, I want a crash-looping backend marked as crashed with its restart count, so that a loop is visible the moment I open crumb.
5. As a developer, I want a backend that exited shown with its exit code and how long ago it died, so that I know my lease is down before I test against it.
6. As a developer, I want each lease's memory use shown, so that I can see what is eating the VPS.
7. As a developer, I want the VPS's available memory in the header, so that I know whether another lease will fit.
8. As a developer, I want branch databases with no lease shown as their own rows with size, so that I can decide whether to drop them.
9. As a developer, I want the lease's port shown, so that I can hit its API directly.
10. As a developer, I want the SYNC column to show whether Mutagen is connected, watching, paused, in conflict or failing, so that I know my edits reach the VPS.
11. As a developer, I want the BUILD column to tell me when files changed after the backend started, so that I know a restart is pending.
12. As a developer, I want the DEPS column to tell me when my lockfile differs from the image's, so that I see a missing-module crash coming.
13. As a developer, I want the SCHEMA column to tell me when my worktree has migrations the branch database lacks, so that I migrate before debugging "relation does not exist".
14. As a developer, I want the WIRED column to tell me whether the frontends point at this lease over loopback, so that live WebSockets work.
15. As a developer, I want to select a lease and read why each layer is behind, so that I know the fix without reading a runbook.
16. As a developer, I want to stream the selected lease's backend logs in a pane, so that I don't need a second terminal.
17. As a developer, I want a command log listing every command crumb ran, in a form I can paste, so that I can trust and reproduce what it does.
18. As a developer, I want the table to refresh every few seconds, so that it reflects reality while I work.
19. As a developer, I want crumb to keep working when the VPS is unreachable, showing the last snapshot and the error, so that a dropped connection is obvious and not fatal.
20. As a developer, I want to reap orphaned leases after seeing the exact list of what will stop, so that cleanup is safe.
21. As a developer, I want reaping to stop orphans first and remove them only after seven days, so that a temporarily missing directory does not cost me a lease.
22. As a developer, I want databases never dropped automatically, so that I never lose data to a cleanup.
23. As an agent or skill, I want `crumb ls --json`, so that I can read lease state without scraping a TUI.
24. As a developer, I want `crumb up <name>` to create everything a lease needs in one step and to be safe to rerun after a failure, so that a half-finished start is fixed by running it again.
25. As a developer, I want ports allocated automatically and locked while allocating, so that two agents starting leases at once never collide.
26. As a developer, I want the Mac-side port forwarded by Mutagen instead of a bare SSH tunnel, so that it survives sleep and network changes.
27. As a developer, I want the frontends' env files written for the lease on up and removed on down, so that frontends follow the lease.
28. As a developer, I want `restart` to wait until my edits are really on the VPS before restarting, so that a restart never boots stale code.
29. As a developer, I want `stop` to free memory while keeping everything, so that idle leases cost nothing and resume quickly.
30. As a developer, I want `down` to remove everything but the database, so that I can come back to the data later.
31. As a developer, I want `drop` to require typing the lease name, so that deleting a database is deliberate.
32. As a developer, I want `migrate` to apply my worktree's migrations to the branch database and restart, so that schema drift is one key.
33. As a developer, I want crumb to refuse to start a second backend on a database that already has one, so that job-queue workers never take each other's jobs.
34. As a developer, I want each branch database to record which worktree created it and when, so that a database without a lease still explains itself.
35. As a developer, I want Orca's worktree removal to run `crumb down`, so that most orphans never happen.
36. As a developer, I want existing leases created by the old script to show up without any migration, so that I can adopt crumb today.
37. As a developer, I want leases to stay stopped after a VPS reboot, so that a reboot does not start every lease at once.
38. As a new user, I want to install crumb with one command through the package manager I already use, so that setup takes seconds.
39. As a new user, I want `crumb init` to detect my compose file, sync config, SSH host, migrations and env files, so that I answer at most a few questions.
40. As a new user, I want `crumb doctor` to tell me exactly what is missing and the command that fixes it, so that I am never stuck on a prerequisite.
41. As a team member, I want the project's `crumb.toml` committed and my machine-specific host in my own config, so that the team shares one setup while each of us uses our own VPS.
42. As a developer without a VPS, I want leases to run on my own machine with Docker Compose, so that crumb is useful without a remote host.
43. As a developer without Docker, I want a lease to run a dev-server command on its own port, so that crumb works for plain Node, Rails or Python projects.
44. As a developer on Neon or Supabase branching, I want the database piece to call my own create and drop commands, so that crumb uses the branching I already have.
45. As a developer, I want any script to act as a driver by reading `CRUMB_*` variables and optionally printing JSON, so that my existing setup scripts work with little change.
46. As a developer, I want command drivers kept out of the refresh loop, so that flexibility never makes the table slow.
47. As a developer, I want `crumb agents install` to install crumb's skill for every agent client on my machine, so that my agents drive crumb correctly.
48. As a developer, I want `crumb agents status` to tell me when an installed skill is older than the installed crumb, so that agents never follow stale instructions.
49. As a team lead, I want `crumb agents install --project` to put the skill in the repo, so that every teammate's agent gets it.
50. As a user of the open skills tooling, I want `npx skills add peaske7/crumb` to work, so that I can install the skill the same way as my other skills.

## Implementation Decisions

Modules (deep modules first):

- **Lease join.** A pure function from Mac-side facts and VPS-side facts to
  lease rows with derived state and per-layer status. It holds all the rules
  (what counts as orphaned, crashed, stopped, database only; how each layer is
  judged). No I/O. This is where most tests live.
- **VPS probe.** A bash script compiled into the binary and sent over SSH on
  stdin, so nothing is installed on the VPS. It prints sectioned output
  (container facts as one JSON object per line, memory, listeners, databases as
  JSON from psql). It never emits container environment variables, because
  they hold secrets. A parser turns the output into VPS facts.
- **Mac facts.** Mutagen sync and forward sessions read through the CLI's JSON
  template output, worktree path existence, lockfile hashes, env-file markers.
- **Command runner.** Runs every external command, records it in the command
  log, and wraps VPS calls in one shared SSH master connection
  (`ControlMaster`, `ControlPersist`, `ClearAllForwardings` because the host
  alias carries the shared tunnel's forwards). Plain `std::process` and
  threads; no async runtime.
- **TUI.** ratatui + crossterm: lease table, detail pane, logs pane, command
  log, key hints. A background thread refreshes the snapshot every 3 seconds
  and sends it over a channel.
- **CLI.** clap: bare `crumb` opens the TUI; `ls [--json]` in v0; lifecycle
  verbs in v1.
- **Config.** Built-in defaults match Lymo today (host `indigo`, replica root
  `~/wt`, VPS ports 8100+nn, Mac ports 18100+nn, Supabase database container).
  An optional `crumb.toml` in the lymo repo overrides them and, in v1, names
  the compose file, the branch-db script, the migrations directory and the env
  files to wire.

Mechanism (agreed 2026-09-28):

- **Identity.** Lease name derived from the worktree directory (lowercase,
  non-alphanumerics become `_`) or given explicitly. Sync `wt-<name>`, forward
  `wt-<name>-api`, compose project `wt_<name>`, database `wt_<name>`, replica
  `~/wt/<name>`. Labels: `crumb.lease` on Mutagen sessions; `crumb.lease`,
  `crumb.port`, `crumb.db`, `crumb.worktree` on containers. Legacy leases are
  recognised by the compose project name, the `lymo-worktree` Mutagen label and
  the published port.
- **Ports.** One number `nn` from 01 to 99 per lease: `81nn` on the VPS,
  `181nn` on the Mac, loopback only on both ends. Loopback is required because
  the realtime client treats only `localhost` and `127.0.0.1` as local and
  upgrades every other `ws:` URL to `wss:`. `nn` is the lowest number unused by
  container labels, Mutagen forwards, VPS listeners and Mac listeners, chosen
  under a `flock` on the VPS. The container label is the record; slot files go
  away. A lease may get a different port after down and up (agreed).
- **Sync.** Unchanged one-way replica plus the label. Readiness means
  `successfulCycles` increased after a flush and status is watching. Stop
  pauses the session; down terminates it and deletes the replica.
- **Containers.** Compose keeps running on the VPS over SSH (running it from
  the Mac would resolve bind mounts and env files to Mac paths). The compose
  file stays in the lymo repo and is streamed to the VPS on each up. Restart
  policy `on-failure:5`, so leases stay stopped after a VPS reboot (agreed).
  Dependency drift is the SHA-256 of the image's `/app/pnpm-lock.yaml`
  (computed once per image id) against the worktree's lockfile.
- **Database.** Created and dropped through Lymo's existing branch-db script.
  crumb adds a database comment with origin metadata. One backend per database
  is enforced before every start. Schema freshness compares the newest
  migration in the worktree with the newest Atlas revision in the database.
- **Lifecycle.** States are derived from the probe. Orphans are stopped at
  once and removed once Docker's `FinishedAt` on the stopped container is seven
  days old (agreed). Databases are removed only by an explicit key with the
  lease name typed. An `orca.yaml` archive hook runs `crumb down`.

Setup, drivers and agents (agreed 2026-09-28):

- **Distribution.** `dist` (cargo-dist) builds one GitHub release for macOS
  and Linux on arm64 and x64, with a checksum-verified shell installer and a
  Homebrew formula published to `peaske7/homebrew-tap`. mise installs the same
  assets through its GitHub backend. The crates.io name `crumb` is taken, so
  the crate is `crumb-cli` and the binary is `crumb`. Windows is out of scope.
- **Config.** `crumb.toml` at the repo root, committed, describes the project.
  `~/.config/crumb/config.toml` holds machine-specific values such as the SSH
  host. Precedence: flags, then `CRUMB_*` environment variables, then the
  user's config, then the repo's. Template variables such as `{lease}`,
  `{port}`, `{local_port}` and values printed by commands (for example
  `{database.url}`) can be used in any string.
- **Pieces and drivers.** Host: local or ssh. Code: none or mutagen. Runtime:
  compose, or process (a command run in a tmux session named
  `crumb-{lease}`, so tmux owns the process). Port: direct, mutagen forward or
  ssh forward. Database: none, postgres copy, or command. Wiring: env files.
  Checks: deps, schema, or command. The driver set is closed; everything else
  is a command. There is no plugin API.
- **Command contract.** crumb sets `CRUMB_LEASE`, `CRUMB_WORKTREE`,
  `CRUMB_PORT`, `CRUMB_LOCAL_PORT` and `CRUMB_HOST`; the command writes
  progress to stderr, exits 0 on success, and may print one JSON object on
  stdout whose fields become template variables and status. Commands run on
  actions and when a lease's details are opened, never in the refresh loop.
  Orca environment recipes and Conductor scripts use the same shape.
- **Init and doctor.** `crumb init` detects, asks at most three questions with
  the detected answer preselected, writes a commented `crumb.toml`, runs
  doctor, and offers to install the agent skill. `--yes` accepts every
  default. `crumb doctor [--json]` checks each configured piece and prints the
  command that fixes each failure.
- **Agent skill.** `crumb agents install|uninstall|status`, with
  `--client claude-code|codex|all` and `--project`. The skill text is
  compiled into the binary, so the installed skill matches the installed
  version and `status` reports drift. Claude Code gets
  `~/.claude/skills/crumb/SKILL.md`, Codex gets
  `~/.codex/skills/crumb/SKILL.md`. The repo also ships
  `skills/crumb/SKILL.md` for `npx skills add peaske7/crumb`. The skill
  replaces the first user's hand-written lease skill.

## Testing Decisions

- Tests exercise external behaviour: given facts in, rows out; given probe
  output in, facts out. They do not assert on internal helpers.
- The lease join gets the most tests, built from the real state captured on
  2026-09-28 (orphans, the crash loop, the exited lease, databases with no
  lease, a legacy lease with no crumb labels).
- The probe parser is tested against captured probe output with secrets
  already excluded by the probe itself.
- The Mutagen parser is tested against captured `--template '{{json .}}'`
  output.
- The TUI and the runner are verified by running crumb against the real VPS;
  no snapshot tests of the terminal.

## Out of Scope

- For the first user's setup: running the backend on the Mac, running the
  frontends on the VPS, and file watchers inside lease containers (they run
  the VPS out of memory).
- Webhooks routed to individual leases.
- The shared, non-lease backend and the main checkout's own sync session (a
  read-only view may come later).
- Named routing (`*.localhost` through a proxy): some WebSocket clients only
  treat `localhost` and `127.0.0.1` as local and upgrade other hosts to `wss:`.
- An image per lockfile hash, idle sleep, and in-place migration of branch
  databases on up (later).
- Windows.
- A plugin API for third-party drivers.

## Further Notes

- The design (identity, ports, sync, containers, databases, lifecycle,
  interface, setup, drivers) is written up in `docs/design.md`.
- Prior art the design borrows from: lazygit and k9s (interface, command
  log), terraform plan (reap shows the plan first), Tilt (per-layer status),
  preview environments (lifetime follows the branch), git worktree prune
  (grace period), DDEV (the cost of auto-deleting on a missing directory),
  Ansible (agentless probe over SSH).
- Independent of crumb, the first user's lease compose file should switch to
  `restart: on-failure:5` and publish on loopback only.
