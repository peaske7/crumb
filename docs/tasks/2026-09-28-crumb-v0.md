## Tasks

### T01 — Tracer: real leases in `crumb ls` and the TUI table

**Type:** AFK
**Status:** Done (2026-09-28)
**Blocked by:** None
**User stories covered:** US1–US9, US18, US19, US23, US36

#### What to build

The thinnest complete path: the probe runs on the VPS over one shared SSH
connection, Mutagen sessions are read on the Mac, the join derives one row per
lease, and the rows appear both in `crumb ls` (plain text and `--json`) and in
a TUI table that refreshes every 3 seconds. Works against today's leases,
which were created by the old script and carry no crumb labels.

#### Acceptance criteria

- [x] `crumb ls` lists every `wt_*` compose project, every lease Mutagen session and every `wt_*` database as rows, with worktree, port, backend state, restarts and memory.
- [x] Leases whose worktree path is gone show as orphaned; a backend with 5+ restarts that is not healthy shows as crashed; an exited backend shows its exit code and age; databases alone show as database only.
- [x] `crumb ls --json` prints the same rows as JSON.
- [x] `crumb` opens the TUI with the table, a header with VPS memory and counts, key hints, `j`/`k` selection and `q` to quit.
- [x] When the VPS is unreachable the TUI keeps the last snapshot and shows the error.
- [x] The probe never outputs container environment variables.
- [x] The join is unit-tested with the state captured on 2026-09-28.

#### Notes

Legacy leases are joined by compose project name, the first user's existing Mutagen
label key and the published port. T01 already reads `crumb.toml` (only the fields
the read path needs: host, compose project pattern, database name pattern,
Mutagen label), so nothing project-specific is hardcoded from the start.

Verified against the first user's VPS on 2026-09-28: 7 leases, 6 orphaned,
one crash loop at 26,000+ restarts, 3 databases without a lease. A warm
`crumb ls` takes about 0.45 s, most of it Docker's own container list on the
host. Orphans sort by name, not memory, so rows stay still while the list
refreshes.

### T02 — Detail pane, logs pane and command log

**Type:** AFK
**Status:** Done (2026-09-28)
**Blocked by:** T01
**User stories covered:** US15, US16, US17

#### What to build

Selecting a lease fills a detail pane with the reason for each state and
layer. `l` streams the selected backend's logs. A command log pane lists
every command crumb ran, pasteable.

#### Acceptance criteria

- [x] Detail pane shows the backend's last error lines for crashed and exited leases.
- [x] `l` follows logs for the selected lease only and stops when the selection changes.
- [x] Every external command appears in the command log with its exit status.

As built, following the interface decisions in `docs/design.md`: the
"detail pane" is the selected row expanding in place, and logs and the
command log are full-screen views left with `esc` or `q`. Error lines come
from a 300-line tail and prefer error headlines (`Error [ERR_…]: …`) over
any line that mentions an error; on the first user's host this surfaced the
missing package behind a 26,000-restart crash loop. The command log folds
repeated refresh commands into one row with a count, and `y` copies through
OSC 52, so it works over SSH without a clipboard program.

### T03 — SYNC and BUILD columns

**Type:** AFK
**Status:** Done (2026-09-28)
**Blocked by:** T01
**User stories covered:** US10, US11

#### What to build

SYNC from Mutagen's JSON (connected, watching, paused, conflicts, last
error). BUILD from the newest source-file time in the replica against the
container's start time, ignoring `dist`, `node_modules` and `.turbo`.

#### Acceptance criteria

- [x] SYNC distinguishes ok, syncing, paused, conflict, error and missing.
- [x] BUILD shows "restart pending" when source changed after start, and "failed" for a non-zero exit.

As built: the sync states arrived with T01 as reasons (paused, not
connected, conflicts, error). The build check compares file times in the
worktree against the container's start, but only under the paths the
container bind-mounts from its project directory (read from `docker
inspect`), so editing the web app never marks the backend stale. A lease
that is behind but healthy stays in the running group and reads "restart
pending"; only broken leases move to "needs you". The walk runs on this
machine, stops at the first changed file, and skips dependency, build-output
and dot directories.

### T04 — DEPS column

**Type:** AFK
**Status:** Done (2026-09-28)
**Blocked by:** T01
**User stories covered:** US12

#### What to build

Hash the image's `/app/pnpm-lock.yaml` once per image id and compare it with
the worktree's lockfile.

#### Acceptance criteria

- [x] A lease whose lockfile gained a dependency after the image was built shows DEPS behind.
- [x] The image hash is computed once per image id per crumb run.

As built: `[checks] deps = { lockfile, image_path }`. The image's lockfile
hash and build time come from one host command per image id (about 0.9 s),
run after the list is first shown and remembered for the session; `crumb ls`
waits for it. A mismatch reads "deps behind" with the image's age.

### T05 — SCHEMA column

**Type:** AFK
**Status:** Done (2026-09-28)
**Blocked by:** T01
**User stories covered:** US13

#### What to build

Compare the newest migration version in the worktree with the newest Atlas
revision in the branch database.

#### Acceptance criteria

- [x] SCHEMA shows behind with both versions in the detail pane.

As built: `[checks] schema = { migrations, query }`. The probe runs the
query in every lease database through one `docker exec` (about 100 ms for
all of them); the newest version is the largest leading number among the
migration file names. A behind lease reads "schema behind" and its details
give both versions and `m`. On the first user's host this showed the shared
database two migrations behind `main`, so every new lease starts behind.

### T06 — WIRED column

**Type:** AFK
**Status:** Done (2026-09-28)
**Blocked by:** T01
**User stories covered:** US14

#### What to build

Read the wired env-file markers in the worktree and
judge them against the lease's forward.

#### Acceptance criteria

- [x] A non-loopback URL shows "tailnet" with the WebSocket warning.
- [x] A loopback URL whose port has no matching forward shows "stale".

As built: `[[wire]]` files carry `# crumb lease <lease>` as their first
line; crumb judges each against what it would write now. A non-loopback URL
reads "wired to <host>" with the WebSocket explanation, anything else
different reads "wiring stale", and a running lease with no forward reads
"no forward". All three are fixed by `t`. `adopt` names the first line of
files an older tool wrote, so crumb may replace them.

### T09 — `crumb up`

**Type:** AFK
**Status:** Done (2026-09-28)
**Blocked by:** T02, T08
**User stories covered:** US24–US27, US33, US34

#### What to build

The idempotent sequence from `docs/design.md`: lock, allocate `nn`,
branch database with origin comment, sync with readiness wait, compose up
with labels, Mutagen forward, env wiring, wait for health.

#### Acceptance criteria

- [x] Rerunning after a failure at any step completes without duplicating resources.
- [ ] Two concurrent `up`s get different ports. (`flock` on the host; verified with T15.)
- [x] `up` refuses when another backend runs on the same database.

As built: `crumb up [--name] [path]`, idempotent step by step: database
(skipped when the server lists it; else the create command, the built-in
copy, or an empty database), an origin comment on it, the sync with a
readiness wait (a new successful cycle while watching, with staging
progress), then one host script under `flock` that picks `nn`, writes the
labels override and runs `docker compose up`, then the Mutagen forward, the
wired files, and Docker's health check. It refuses when another running
container is labelled with the same database, and when the lease name
belongs to a different worktree. First run on the first user's host: 4 min
12 s, of which 3 min was the first 167 MB sync; a rerun takes about 40 s.

### T10 — restart, stop, down, drop, migrate, tunnel

**Type:** AFK
**Status:** Done (2026-09-28)
**Blocked by:** T09
**User stories covered:** US28–US32

#### Acceptance criteria

- [x] `restart` waits for sync readiness before restarting.
- [x] `drop` requires typing the lease name.

As built: `restart` resumes and waits for the sync before `docker restart`,
then waits for health; `stop` stops containers and pauses sync and forward;
`down` removes containers, forward, sync, replica, compose state, the old
script's slot file and the wired files, and keeps the database; `drop`
needs the lease name typed (TUI) or `--confirm <name>`; `migrate` runs the
configured command in the worktree, then restarts; `tunnel` recreates the
forward and rewrites the wired files. All are keys in the TUI, where they
run on a thread and report their steps in place of the lease's status.

### T12 — `crumb init` and `crumb doctor`

**Type:** AFK
**Status:** Done (2026-09-28)
**Blocked by:** T01
**User stories covered:** US39, US40, US41

#### What to build

`init` detects compose files, `mutagen.yml`, SSH hosts, migrations
directories and env files that point at a local port, asks at most three
questions with the detected answer preselected, writes a commented
`crumb.toml`, runs doctor and offers the agent skill. `doctor [--json]`
checks each configured piece and prints the fixing command for each failure.

#### Acceptance criteria

- [x] `crumb init --yes` in the first user's repo produces a config equivalent to the VPS example in `docs/design.md`.
- [x] On a machine without Mutagen, doctor fails that check and prints the install command.
- [x] `~/.config/crumb/config.toml` overrides the repo's host.

As built: `init` detects the compose file (preferring one named for
worktrees), the service that publishes a port, the host from mutagen.yml,
the lockfile, Atlas or Rails migrations and env files with a local API URL,
asks three questions (host, compose file, service), writes a commented
crumb.toml and runs doctor. `doctor [--json]` checks the config, SSH (timed),
Docker, compose, the env file, flock, the database, Mutagen, the ignore
file, the compose file and the agent skill in one host round trip, and
exits non-zero on a failure. The user config now overrides the project
config, as the design says.
